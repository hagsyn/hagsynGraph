# Hagsyn Product Roadmap

## 文档目标

定义 Hagsyn 当前阶段的产品路线图，明确从“已有工作台壳与首个真实工具”出发，后续应如何有序扩展。

## 路线图原则

Hagsyn 的 roadmap 不以“页面数量”或“概念完整度”为目标，而以真实可用性和长期产品结构稳定性为主。

当前路线图应遵循四个原则：

1. 先稳住真实工具主线
2. 再补统一的产品与交互规则
3. Knowledge 模块由真实场景触发
4. 每一阶段都尽量保留当前工作台壳的连续性

## 当前阶段基线

截至当前版本，Hagsyn 已具备以下基线：

- 工作台骨架已形成：`Dashboard / Tools / Nodes / Graph / Roadmaps`
- `Tools` 中已有首个真实工具：视频压缩
- 后端已具备本地 API、鉴权和文件处理基础
- 前端已具备本地单页工作台入口

这意味着后续 roadmap 的起点，不是“从零设计一个产品”，而是在已有母体上继续做深。

## Phase 1：稳住 MVP

### 目标

把当前“工作台壳 + 视频压缩”打磨成一个稳定、可信、可反复使用的本地工具产品。

### 重点事项

- 稳定视频压缩上传、处理、下载闭环
- 完善错误反馈和结果反馈
- 保持 `Tools` 页面的主工作区语义
- 保持 `Dashboard / Nodes / Graph / Roadmaps` 的骨架稳定

### 成功标志

- 视频压缩可持续可用
- 页面结构清晰，不像 demo
- 用户进入产品后能明确知道第一步该做什么

## Phase 2：建立工具产品化规则

### 目标

把当前首个真实工具的经验整理成可复用的接入规则，为后续新增工具做准备。

### 重点事项

- 明确什么能力可以进入 `Tools`
- 统一工具目录、工具工作区、结果区和说明区模式
- 统一工具卡片信息表达
- 明确工具状态、输入要求和输出格式的呈现原则

### 成功标志

- 新工具接入时不需要重新发明页面结构
- `Tools` 模块形成稳定的产品语言

## Phase 3：按真实需求扩展第二批工具

### 目标

在不破坏当前壳的前提下，接入第二批真正有价值的工具。

### 进入条件

- 已有工具稳定可用
- 新工具对应明确高频场景
- 接入后不会只是占位卡片

### 建设原则

- 单次只扩一个小批次
- 每个新工具都要有完整闭环
- 不因为“看起来丰富”而牺牲质量

## Phase 4：开启 Knowledge 主线的真实建设

### 目标

当 Tools 主线已经积累起真实使用经验后，逐步把这些经验沉淀为结构化知识模块。

### 可启动信号

- 工具开始出现稳定使用经验
- 某些场景、问题、参数选择开始可复用
- 用户开始需要“记住为什么这样做”和“下次如何复用”

### 可能的建设方向

- `Nodes`：沉淀真实对象，如工具、场景、经验、模板、问题
- `Graph`：表达对象之间的适用、依赖、替代和组合关系
- `Roadmaps`：组织工具接入路线、场景解决路线或学习路径

### 边界要求

- 不灌 demo 数据
- 不先设计过重的数据模型
- 不把 Knowledge 当作当前阶段的主价值来源

## Phase 5：形成产品体系闭环

### 目标

让 Hagsyn 从“有一个真实工具的工作台”成长为“有稳定工具层、可持续知识层和统一产品规则的本地系统”。

### 成熟表现

- `Tools` 持续承载真实任务
- `Knowledge` 承接真实沉淀
- `Dashboard` 能真实反映建设进展
- 文档、工程和 UX 规范能支持长期迭代

## 当前优先级排序

当前建议的优先级从高到低为：

1. 视频压缩主线稳定性
2. `Tools` 产品模式收敛
3. 工作台整体信息架构稳定
4. Knowledge 模块等待真实场景进入
5. 更长期的知识化组织和路线能力

## 当前 roadmap 结论

Hagsyn 近期最重要的事情不是横向铺开很多能力，而是围绕一个真实工具把产品骨架和产品方法论立住。

只要这条路线走稳，后续无论新增更多工具，还是逐步让 `Nodes / Graph / Roadmaps` 真正活起来，都会有清晰、可信的产品演进路径。
