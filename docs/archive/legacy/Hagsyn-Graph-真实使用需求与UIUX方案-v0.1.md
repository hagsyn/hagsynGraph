# Hagsyn Graph 真实使用需求与 UI/UX 方案 v0.1

> 目标：把当前 MVP 从“展示页面”推进为真正可用的个人 AI 工具库和知识图谱工作台。

---

## 1. 真实使用目标

Hagsyn Graph v0.1 的真实使用目标不是做一个漂亮首页，而是让用户每天可以完成三件事：

1. **快速记录**：看到一个 AI 工具、框架、模型、教程或项目想法时，能快速录入。
2. **建立判断**：能给工具打标签、标状态、评估重要度和商业价值。
3. **形成路线**：能把工具、场景、项目和学习步骤连接起来，形成自己的 AI 作战地图。

---

## 2. 当前 MVP 的问题

当前页面主要问题：

- 页面像静态展示，不像真实工作台。
- 缺少明确的主操作入口。
- Tools、Nodes、Graph、Roadmaps 之间关系不够清楚。
- 图谱只是展示，不能辅助判断和行动。
- 缺少详情面板、编辑、删除、关系创建等真实操作。
- 没有围绕“今天我要整理什么工具/路线”来设计。

---

## 3. v0.1 真实闭环

第一版必须跑通 5 个闭环：

### 3.1 工具录入闭环

用户可以：

- 新增工具
- 填写简介、链接、标签
- 设置学习状态
- 设置重要度和商业价值
- 保存后立即出现在工具目录

### 3.2 节点管理闭环

用户可以：

- 新增任意类型节点
- 按类型、状态、标签搜索
- 查看节点详情
- 删除无效节点

### 3.3 关系建立闭环

用户可以：

- 选择 A 节点
- 选择关系类型
- 选择 B 节点
- 添加备注
- 在 Graph 页面看到关系

### 3.4 路线管理闭环

用户可以：

- 创建路线图
- 添加路线步骤
- 给步骤标记状态
- 将步骤绑定到已有节点

### 3.5 决策辅助闭环

Dashboard 应该回答：

- 最近我新增了什么？
- 哪些工具商业价值最高？
- 哪些工具还没研究？
- 当前重点方向是什么？
- 哪些节点还没有关系，需要整理？

## 4. 信息架构

### 4.1 页面导航

| 页面 | 真实用途 | 主操作 |
|---|---|---|
| Dashboard | 今日总览和待处理事项 | 查看重点、继续整理 |
| Tools | AI 工具目录 | 新增工具、筛选工具、查看详情 |
| Nodes | 全量知识节点 | 管理工具以外的模型、框架、场景、资源、项目 |
| Graph | 关系图谱 | 建立关系、查看连接 |
| Roadmaps | 学习路线 / 项目路线 | 创建路线、添加步骤 |

### 4.2 Tools 和 Nodes 的区别

- **Tools**：给高频使用，专门管理 `tool` 类型，体验要像一个工具雷达。
- **Nodes**：给全量管理，覆盖所有类型，体验要像一个数据库后台。

## 5. UI/UX 设计方向

### 5.1 设计原则

1. **操作优先**：每个页面都要有明确主按钮。
2. **信息密度适中**：个人工具库需要快速扫读，不能只有大卡片。
3. **少装饰，多判断**：不要为了科技感堆渐变和假数据。
4. **详情侧栏化**：点击节点后，右侧显示详情和下一步行动。
5. **可持续录入**：新增表单要轻，不要每次都像填复杂档案。

### 5.2 推荐布局

采用三栏式工作台：

```txt
左侧导航 | 中间主列表/图谱 | 右侧详情/操作面板
```

移动端或窄屏时，右侧详情改为弹窗。

### 5.3 视觉风格

- 暗色底色，但减少强渐变。
- 类似 Linear / Raycast 的克制软件质感。
- 用颜色表达节点类型，而不是装饰页面。
- 强调清晰、速度、可维护。

## 6. MVP 交互清单

### 6.1 必须补齐

- 工具新增表单
- 节点新增表单
- 节点搜索
- 类型筛选
- 状态筛选
- 节点详情面板
- 节点删除
- 关系创建表单
- 路线创建表单
- 路线步骤添加
- Graph 页面显示关系

### 6.2 暂不做

- 登录
- 多用户
- AI 自动导入 URL
- 自动布局算法
- 高级图谱分析
- 权限管理
- 云端同步

## 7. 示例数据调整

当前项目不再使用 ComfyUI 作为核心示例。

推荐示例数据：

- Hermes Agent：个人智能助手底座

- Cursor：AI 编程工具
- 知识库问答：高价值应用场景
- 企业知识库助手：可商业化项目
