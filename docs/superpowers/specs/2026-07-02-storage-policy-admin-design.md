# Storage Policy Admin Design

## 目标

为 Hagsyn 增加一个“存储与清理策略”能力，用于管理工具运行产生的文件生命周期。

该能力需要满足：

1. 清理策略可在页面中配置
2. 只有管理员可以查看和修改
3. 当前默认账号 `hagsyn` 视为管理员
4. 普通用户只能使用工具，不能调整清理规则

---

## 一、为什么现在要做

当前 Hagsyn 已有两个真实工具：

- 视频压缩
- VTT 字幕生成

这两个工具都会在服务器/本机环境中留下文件：

- 原始上传文件
- 压缩结果文件
- 字幕结果文件
- 字幕中间音频文件

目前这些文件会落盘，但不会自动清理。

这意味着：

- 文件会不断累积
- 中间文件会占空间
- 出错任务的临时文件也可能残留

因此需要一个真正可配置的清理策略层，而不是依赖手工删除。

---

## 二、权限前提

当前阶段采用明确前提：

- 默认账号 `hagsyn` = 管理员

该前提用于支持第一版轻量权限控制，不引入复杂 RBAC。

### 管理员能力

- 查看清理策略
- 修改清理策略
- 手动触发清理

### 普通用户能力

- 使用工具
- 不可见清理策略配置
- 不可触发清理

---

## 三、前端入口设计

推荐入口：

- 右上角用户菜单
  - 用户信息
  - 设置
  - 退出登录

其中 `设置` 打开后，管理员可见：

- `存储与清理策略`

普通用户：

- 不显示该项
  或
- 显示但不可进入

推荐第一版采用“不显示”，交互更干净。

---

## 四、推荐配置项

第一版建议只做 6 个配置项：

1. `启用自动清理`
2. `原始上传文件保留时长`
3. `压缩结果文件保留时长`
4. `字幕结果文件保留时长`
5. `字幕中间音频立即删除`
6. `失败任务临时文件立即清理`

这些配置已经足够覆盖当前真实文件生命周期问题。

---

## 五、后端接口设计

建议新增管理员接口：

- `GET /api/admin/storage-policy`
- `PUT /api/admin/storage-policy`
- `POST /api/admin/storage-policy/run-cleanup`

### 接口职责

#### `GET /api/admin/storage-policy`

返回当前策略配置。

#### `PUT /api/admin/storage-policy`

更新当前策略配置。

#### `POST /api/admin/storage-policy/run-cleanup`

立即执行一次清理。

该接口返回：

- 清理了多少文件
- 释放了多少空间
- 哪些目录参与了清理

---

## 六、配置存储方案

推荐第一版使用本地配置文件：

- `backend/storage_policy.json`

原因：

- 当前是本地单机工具工作台
- 配置项数量少
- 上手快
- 不需要先建配置表和迁移逻辑

后续如果需要更复杂的账户与环境配置，再迁移到数据库。

---

## 七、清理执行策略

建议拆成两层：

### 1. 即时清理

在工具运行链路中直接执行：

- 字幕中间 `.wav` 文件生成完成后立即删除
- 失败任务的临时文件立即删除

### 2. 定时/手动清理

由清理策略控制：

- 上传文件保留多久
- 压缩结果保留多久
- 字幕结果保留多久

并允许管理员手动点击：

- `立即清理`

---

## 八、页面交互建议

设置区不建议单独做一个新页面。

推荐使用：

- 用户菜单 -> 设置
- 设置弹层 / 面板

其中包含一个分组：

- `存储与清理策略`

字段应使用明确表单表达，不做抽象词。

推荐交互：

- 开关：启用自动清理
- 下拉/数字输入：保留时长
- 开关：中间音频立即删除
- 开关：失败任务临时文件立即清理
- 按钮：保存配置
- 按钮：立即清理

---

## 九、与当前工具的关系

该能力是工具层的支撑能力，不是新的主模块。

它不进入：

- Dashboard
- Tools 工具卡
- Nodes / Graph / Roadmaps

它属于：

- 全局设置能力
- 管理员控制能力
- 文件生命周期治理能力

---

## 十、推荐实施顺序

### Phase 1

- 增加本地配置文件模型
- 增加管理员接口
- 增加字幕中间 `.wav` 立即删除
- 增加失败任务临时文件立即清理

### Phase 2

- 增加前端设置弹层
- 管理员可修改清理策略
- 支持手动“立即清理”

### Phase 3

- 视需要补自动定时清理
- 补清理日志或历史摘要

---

## 十一、推荐结论

推荐继续推进，而且当前就值得做。

因为这不是“为了更像产品”的配置项，而是当前真实工具运行后立刻会碰到的文件生命周期问题。

最合理的做法是：

1. 先将 `hagsyn` 视为管理员
2. 将清理策略放在设置里
3. 第一版用本地配置文件存储
4. 第一版先做即时清理 + 手动清理
5. 后续再补自动清理
