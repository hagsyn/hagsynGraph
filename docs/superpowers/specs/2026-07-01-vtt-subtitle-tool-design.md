# VTT Subtitle Tool Design

## 目标

在 Hagsyn 的 `Tools` 模块中新增第二个真实工具：`VTT 字幕生成`。

该工具的目标是：

1. 用户上传视频文件
2. 系统抽取音频
3. 执行语音识别
4. 生成 `.vtt` 字幕文件
5. 返回结果卡片并提供下载

这是一个真实可执行工具，而不是知识模块、图谱模块或路线模块的扩展。

---

## 一、模块落点

该能力应明确落在：

- `Tools`

不应落在：

- `Dashboard`
- `Nodes`
- `Graph`
- `Roadmaps`

原因：

- 它有明确输入
- 有真实处理过程
- 有明确输出
- 能形成完整用户闭环

因此它符合当前 Hagsyn 对“真实工具”的定义。

---

## 二、当前阶段定位

建议定位为：

- 第二个真实工具
- `Next` 优先级
- 当前阶段适合做 MVP，不适合一开始做复杂字幕编辑器

当前阶段不建议扩成：

- 在线字幕编辑器
- 多语言字幕管理台
- 说话人分离系统
- 字幕审核平台

---

## 三、推荐实现路线

推荐路线：

### 本地 MVP 路线

使用：

- `ffmpeg` 抽音频
- 本地语音识别引擎做转写
- 转换为 `vtt`

推荐理由：

- 符合当前“本地单机工具工作台”路线
- 避免当前 Google API 网络不稳定问题
- 和视频压缩工具在产品形态上高度一致

---

## 四、能力边界

首版只做：

1. 上传视频
2. 选择语言策略：
   - 自动识别
   - 中文
   - 英文
3. 生成 `.vtt`
4. 展示结果卡片
5. 下载字幕文件

首版不做：

- 字幕编辑
- 时间轴手工校正
- 多轨字幕
- 字幕翻译
- 说话人分离
- 批量任务

---

## 五、工具工作区设计

该工具应继续复用当前 `Tools` 工作区模式。

### 中间主工作区

建议包含：

1. 上传区
   - 选择视频文件
   - 显示支持格式

2. 参数区
   - 语言选择
   - 简要说明转写策略

3. 执行区
   - 开始生成按钮
   - 当前状态

4. 结果区
   - 文件名
   - 生成状态
   - 字幕条数或片段数
   - 下载按钮

### 右侧详情栏

建议包含：

1. 工具说明
2. 当前支持格式
3. 当前边界
4. 语言策略说明
5. 结果文件说明

---

## 六、后端链路设计

建议后端新增一条新的工具链路：

1. 接收上传视频
2. 将视频抽音频到临时文件
3. 调用本地识别引擎获取分段文本
4. 将分段文本写入 `.vtt`
5. 返回结果元信息与下载地址

建议路径风格保持与现有工具一致：

- `POST /api/tools/vtt-subtitle`
- `GET /api/tools/vtt-subtitle/files/{file_id}`

---

## 七、结果数据设计

结果 JSON 建议至少包含：

- `fileId`
- `originalName`
- `language`
- `subtitleFormat`
- `segmentCount`
- `downloadUrl`
- `outcome`

其中：

- `subtitleFormat` 当前固定为 `vtt`
- `outcome` 用于表达生成是否成功

---

## 八、错误处理要求

需要明确处理以下失败边界：

1. 文件格式不支持
2. 音频抽取失败
3. 本地语音识别依赖不可用
4. 字幕生成失败
5. 下载文件不存在

前端不能只显示泛化失败弹窗，应尽量把错误边界收成可理解提示。

---

## 九、回归测试要求

根据当前仓库规则，这个功能做完后必须补回归测试。

至少应包含：

1. 路由存在测试
2. 不支持格式拒绝测试
3. 成功返回字幕下载信息测试
4. 依赖不可用时的错误测试
5. `.vtt` 基本格式输出测试

---

## 十、推荐结论

推荐继续推进该工具，作为：

- `Tools` 下第二个真实工具
- 本地 MVP 路线
- 小而真的闭环能力

当前最合适的做法是：

1. 先保持它是字幕生成器，而不是字幕平台
2. 先复用现有工具工作区模式
3. 先把本地生成 `.vtt` 跑通
4. 完成后立即补对应回归测试
