# Subtitle Quality Refinement Design

## 目标

为 `VTT 字幕生成` 和 `视频字幕烧录` 增加共享的字幕文本质量增强能力，重点提升转写文本的语言正确性、词组完整性和上下文连贯性。

该能力不应把 Hagsyn 扩展成完整字幕编辑平台，也不应凭空创作字幕内容。它只在本地转写结果基础上做保守修正，让输出更贴近真实语音内容和实际语境。

---

## 一、问题背景

当前字幕链路在 `backend/app/subtitle_tools.py` 中完成：

1. `ffmpeg` 抽取音频
2. `faster-whisper` 转写为 segments
3. `render_vtt_lines` 输出 VTT
4. `视频字幕烧录` 复用同一份 VTT，再转 SRT 并烧录进视频

实际使用中，转写文本可能出现：

- 常见词组被拆散
- 同音或近音词识别错误
- 中文标点和断句不自然
- 相邻字幕语义衔接差
- 重复口癖、空白、异常标点影响阅读

这些问题会同时影响：

- 下载的 `.vtt` 文件
- 烧录到视频里的字幕

因此优化应进入共享字幕质量层，而不是分别在两个工具里各写一套逻辑。

---

## 二、产品边界

本次能力仍属于：

- `Tools`

不进入：

- `Knowledge`
- `Nodes`
- `Graph`
- `Roadmaps`

本次做：

1. 转写后文本清理
2. 词组和术语保护
3. 保守的中文/英文标点与空格规范
4. 相邻 segment 的上下文连贯性检查
5. 两个字幕工具共享同一增强结果

本次不做：

- 在线字幕编辑器
- 人工审核工作流
- 多版本字幕管理
- LLM 自由改写
- 翻译
- 说话人分离
- 基于音频二次对齐的时间轴重算

---

## 三、设计原则

### 1. 忠实优先

修正应尽量贴近原转写结果和用户选择的语言策略。不能为了通顺而改变语义。

### 2. 保守增强

只有当规则明确、词表明确或上下文证据足够时才修正。

### 3. 共享链路

质量增强发生在 `generate_vtt_subtitle` 内部的 normalized segments 之后、VTT 渲染之前。

这样：

- `VTT 字幕生成` 自动获得增强后的 VTT
- `视频字幕烧录` 自动使用增强后的 VTT 转 SRT

### 4. 可配置扩展

第一版词组和纠错规则可以放在代码模块中，后续再升级为配置文件或用户词库。

### 5. 可测试

所有增强逻辑应可通过纯函数测试，不依赖真实 `ffmpeg`、真实模型或浏览器。

---

## 四、推荐架构

新增模块：

- `backend/app/subtitle_refinement.py`

职责：

1. 定义 `SubtitleSegment`
2. 暴露 `refine_subtitle_segments(segments, language)`
3. 对每条 segment 做文本清理
4. 对相邻 segment 做轻量上下文合并或标点修正
5. 输出仍为现有 renderer 可消费的 `list[dict]`

`backend/app/subtitle_tools.py` 只负责调用：

```python
normalized_segments = [...]
refined_segments = refine_subtitle_segments(normalized_segments, language)
rows = render_vtt_lines(refined_segments)
```

## 五、第一版增强规则

### A. 基础清理

适用于所有语言：

- 合并多余空白
- 去掉重复标点
- 去掉连续重复口癖，例如 `呃 呃`、`啊 啊`
- 保留原始时间轴

### B. 中文规则

当 `language == "zh"` 或自动识别结果明显包含中文时：

- 移除中文字符之间多余空格
- 修正中英文混排中多余空格
- 用中文标点改善断句
- 保护常见技术词组，例如：
  - `Hagsyn`
  - `VTT`
  - `ffmpeg`
  - `API`
  - `Tools`
  - `字幕烧录`
  - `视频压缩`

### C. 英文规则

当 `language == "en"` 或文本以英文为主时：

- 合并多余空格
- 基础句首大写
- 常见技术词大小写保护，例如 `API`、`VTT`

### D. 上下文连贯性

第一版只做轻量检查：

- 如果相邻两条字幕文本都很短、时间间隔很小，并且第一条没有明显结尾标点，可在渲染前补充更自然的连接标点
- 不合并时间段，不移动时间轴
- 不跨越明显句末标点做语义合并

---

## 六、API 与前端影响

本次不改 API 路径和返回结构。

仍然保持：

- `POST /api/tools/vtt-subtitle`
- `POST /api/tools/video-subtitle-burn`

前端可以暂不新增开关，默认启用保守增强。

后续如果用户希望对比原始字幕和优化字幕，可再新增高级选项。

---

## 七、测试策略

新增测试应覆盖：

1. 中文字符之间空格清理
2. 常见技术词组保护
3. 重复口癖和重复标点清理
4. 英文句首和术语大小写
5. 相邻 segment 连贯性规则
6. `generate_vtt_subtitle` 调用质量增强后的结果
7. `generate_burned_subtitle_video` 继续复用同一份增强结果

验证方式：

- 纯函数单测优先
- API mock 测试补充链路覆盖
- 不依赖真实大视频作为常规回归

---

## 八、成功标准

本任务完成后，应满足：

1. 两个字幕工具都使用同一套增强后的字幕文本
2. 基础错词、词组和标点问题有可测试规则覆盖
3. 不改变时间轴
4. 不改 API 返回结构
5. 后端测试全部通过
6. 测试报告记录本轮字幕质量增强范围和限制

---

## 九、明确限制

第一版不会保证所有转写错误都能修正。

尤其以下情况不在本轮解决：

- 模型完全听错的专有名词
- 需要领域知识才能判断的语义
- 音频质量差导致的大段误识别
- 需要人工审校才能判断的字幕语义

本轮目标是让常见、可规则化、低风险的问题自动改善，并为后续更强的词库或 LLM 校对留下接口。
