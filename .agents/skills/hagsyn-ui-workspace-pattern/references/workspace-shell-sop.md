# Workspace Shell SOP

## 适用场景

用于以下类型的前端任务：

- 调整 `Tools` 模块整体布局
- 修改左侧导航、中间主工作区、右侧上下文栏之间的关系
- 新增页面壳层、模块入口、导航切换或整体信息架构
- 把某个工具页并回产品工作台，或避免页面漂移成独立展示页

## 前置检查

1. 确认当前任务是否真的涉及工作区壳层，而不是单个控件微调。
2. 查看现有页面是否仍以 `Tools` 工作区为主入口，而不是 landing page。
3. 确认右侧区域当前承担的内容类型：状态、说明、历史、结果细节或边界提醒。
4. 检查任务是否会引入新模块、新导航层级或新的整页视觉语言。

## 执行步骤

1. 先定义三段职责：
   - 左侧负责导航、工具列表或模式切换
   - 中间负责当前工具的核心操作闭环
   - 右侧负责与当前状态强相关的上下文信息
2. 若要新增或调整页面结构，优先在现有工作台壳层内完成，不把工具流程拆成独立展示页。
3. 中间区域始终让当前工具任务成为主视觉焦点，不用大段品牌介绍、英雄区或展示卡墙替代操作面。
4. 右侧区域必须有明确用途；若当前状态没有复杂细节，可展示边界说明、步骤提示、模式差异或最近结果摘要。
5. 导航与布局调整后，确保用户仍能快速回到工具入口，并保持工作区内切换连贯。

## 自校验步骤

1. 页面是否仍可被解释为左导航 / 中操作 / 右上下文的工作区，而不是单栏页面。
2. 主区域是否优先服务真实工具操作，而不是信息展示。
3. 右侧区域是否承载了与当前状态有关的有用信息。
4. 新布局是否保持 `Tools` 为当前产品重心，没有把主体验改成展示壳。
5. 同一任务是否可以在当前壳层内闭环完成，而不需要跳到另一个风格完全不同的页面。

## 常见失败点

- 把中间区域做成大面积介绍页，真实工具入口被挤到次级位置。
- 右侧栏只剩装饰文案或重复标题，没有状态价值。
- 新增模块时直接引入 dashboard 或 showcase 风格，破坏工作台一致性。
- 为了“丰满页面”加入和当前工具无关的统计卡片或假数据区。
