# Tool Workspace SOP

## 适用场景

用于以下类型的前端任务：

- 新增工具工作区
- 调整上传、配置、执行、结果、下载等核心操作流
- 修改工具主面板中的状态切换、结果呈现或操作顺序
- 统一多个工具的工作区模式

## 前置检查

1. 明确当前工具的真实闭环是什么，例如上传、选择模式、执行压缩、下载结果。
2. 确认任务是否会改变核心流程顺序、主操作按钮位置或结果回看方式。
3. 检查当前设计里是否出现与真实操作无关的展示内容。
4. 若是新工具，先抽取它和现有工具共享的工作区结构，而不是单独发明页面组织方式。

## 执行步骤

1. 先写出该工具的最短成功路径，并让主工作区围绕这条路径组织。
2. 将输入、配置、执行状态、结果查看、下载或后续动作放在同一主工作区里，减少跨页跳转。
3. 对结果态保持可扫描性：用户应能快速看见输出文件、状态、关键指标和可执行下一步。
4. 如需展示模式说明、限制条件、历史记录或执行细节，优先放到右侧上下文栏，而不是打断主流程。
5. 多工具复用工作区时，复用布局节奏和交互语法，但允许工具内容本身保持真实差异。

## 自校验步骤

1. 用户是否能在一个连续工作区内完成“进入工具到拿到结果”的主路径。
2. 主区域是否清楚区分输入态、执行态和结果态。
3. 结果信息是否足够支持继续动作，例如下载、重试、修改模式。
4. 说明性内容是否被放到辅助位置，没有压过主操作。
5. 整体模式是否像真实工具，而不是案例展示或产品介绍。

## 常见失败点

- 结果页和输入页割裂，用户需要跳到别的页面才能下载或重试。
- 把说明文案堆到主操作区，导致工具本身不突出。
- 用大块概念介绍替代真实状态呈现，例如只有“能力说明”没有当前结果。
- 为了统一而过度抽象，反而让具体工具缺少必要操作。
