# Empty State And Detail Panel SOP

## 适用场景

用于以下类型的前端任务：

- 设计无数据、未登录、未上传、未执行、无结果等空状态
- 调整右侧详情栏中的说明、状态、历史或边界信息
- 增加占位内容、提示文案、行动引导
- 处理“先有壳层，后补真实能力”的保守界面状态

## 前置检查

1. 确认该状态为什么为空：尚未开始、用户未提供输入、能力未完成，还是当前确实无结果。
2. 检查右侧栏是否已经有明确职责，避免和主区内容重复堆叠。
3. 核对页面上是否存在任何虚构数据、假文件名、伪分析结果或演示记录。
4. 明确空状态下用户下一步最该做的动作是什么。

## 执行步骤

1. 空状态文案只说明当前真实状态和下一步动作，不编造示例业务成果。
2. 如果需要占位内容，优先使用边界说明、操作提示、模式差异、输入要求或真实限制条件。
3. 右侧详情栏围绕当前状态提供补充价值，例如当前模式解释、输入规范、最近一次真实结果摘要或失败原因。
4. 当主区没有数据时，右侧栏可以承担更多说明职责，但仍需和当前工具状态直接相关。
5. 对未完成能力保持诚实表述，可保留轻量入口或保留位，但不要伪装成已经可用的完整功能。

## 自校验步骤

1. 页面是否没有使用假图谱、假统计、假文件或假历史来填空。
2. 空状态是否明确告诉用户现在是什么状态、下一步做什么。
3. 右侧栏内容是否确实补充了主区，而不是重复主标题或空泛宣传。
4. 如果能力尚未落地，界面是否清楚表现为保留位或边界状态。
5. 文案和结构是否仍然服务真实工具使用，而不是把空状态做成营销素材。

## 常见失败点

- 为了避免页面显空，加入虚构数据集、图表或业务指标。
- 右侧栏照搬主区文案，没有额外上下文价值。
- 空状态只说“暂无数据”，没有下一步动作。
- 尚未完成的能力被包装成已经可运行的完整模块，造成误导。
