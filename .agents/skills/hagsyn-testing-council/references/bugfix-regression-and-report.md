# Bugfix Regression And Report SOP

## 适用场景

当修复线上或手测发现的问题时使用，尤其是已经有明确报错截图、错误文案或错误行为的 bug。

## 前置检查

1. 明确 bug 的真实症状
2. 明确根因是否已经被定位
3. 找出最合适的自动回归测试层级：
   - 后端 API
   - 前端结构
   - 交互行为

## 执行步骤

1. 先写或补一条能锁住该问题的回归测试
2. 确认测试在修复前会失败，或至少能证明旧问题未被覆盖
3. 修复实现
4. 再跑受影响测试，确认转绿
5. 在测试报告中记录：
   - 问题表现
   - 根因
   - 修复点
   - 新增回归测试
   - 当前验证结果

## 自校验步骤

1. 这次 bug 是否有明确的自动回归覆盖
2. 报告里是否写清楚“问题 -> 根因 -> 修复 -> 验证”
3. 是否避免只靠口头说明“已经修了”
4. 是否把用户实际看到的问题语义纳入验证

## 常见失败点

- 修 bug 但不补测试
- 只补了存在性测试，没有锁住真实问题
- 报告只写“已修复”，没有根因和验证依据
