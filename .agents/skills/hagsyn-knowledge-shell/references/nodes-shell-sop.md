# Nodes Shell SOP

## 适用场景

当任务涉及 `Nodes` 模块的工作区设计、对象列表结构、对象类型边界、节点预览区或空状态表达时使用。

## 前置检查

1. 确认当前是否已有真实知识对象来源
2. 确认任务是在做“对象本体层”的工作，而不是关系图或路线图
3. 确认页面是否会被假数据诱导成“已完成节点库”

## 执行步骤

1. 保持 `Nodes` 的核心角色为“知识对象本体层”
2. 先设计对象工作区骨架，而不是提前灌列表内容
3. 主区优先承载：
   - 节点筛选骨架
   - 节点列表容器
   - 节点预览区
   - 沉淀来源说明
4. 右侧详情栏说明：
   - 当前模块职责
   - 节点类型边界
   - 当前录入原则
5. 当没有真实节点时，用诚实空状态说明来源方向和进入条件

## 自校验步骤

1. `Nodes` 是否仍然像对象工作区，而不是假列表页
2. 是否没有灌 demo 节点
3. 是否明确区分对象本体与关系/路线职责
4. 是否让“未来如何进入真实对象”清楚可见
5. 是否没有和 `Tools` 目录产生语义重叠

## 常见失败点

- 用大量示例节点填空
- 把 `Nodes` 做成第二个 `Tools`
- 没有对象预览结构，只剩一句空状态
- 提前定义过重的对象体系，却没有真实来源支撑
