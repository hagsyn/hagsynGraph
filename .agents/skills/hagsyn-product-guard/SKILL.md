# Hagsyn Product Guard

## When to Use

Use this skill when work involves:

- product positioning, roadmap, or scope decisions
- new pages, workspace sections, or navigation changes
- deciding whether a capability belongs in `Tools` or `Knowledge`
- refactoring the shell around the current video compression workflow
- proposing placeholder data, fake graph content, sample dashboards, or showcase flows

Do not use this skill for narrow implementation details that do not affect product direction or module boundaries.

## Global Rules

- Keep Hagsyn-Graph aligned to a real local video-compression tool path, not a showcase shell.
- Prefer real workflows and executable value over fake data, placeholder entities, or presentation-only surfaces.
- Keep the workspace shell, but do not let the shell pretend unfinished modules are already validated products.
- Treat `Tools` as the current value center for practical capabilities.
- Keep `Knowledge` at shell stage unless there is real scenario evidence, real content source, and real operational demand.
- When a proposal fails these checks, shrink it toward a smaller and more real tool-first version before accepting it.
