# Demo-Driven Drift Guard SOP

## 适用场景

当任务涉及产品方向、功能规划、页面概念稿、空状态设计、示例数据、展示型流程或“先做个看起来完整的版本”这类提议时使用。

## 前置检查

1. 确认当前提议是否会新增假数据、样例实体、展示型图谱、伪工作流或不可执行的页面内容
2. 确认任务是否直接服务当前 MVP 主路径：上传视频、选择压缩模式、完成压缩、返回下载结果
3. 判断提议是在补真实闭环，还是主要在补“看起来更像产品”的外观完整度

## 执行步骤

1. 用一句话描述这项变更的真实用户价值，不能只写“更完整”“更好看”“更像平台”
2. 检查变更是否依赖以下内容之一：
   - fake data
   - mock knowledge cards
   - showcase graph
   - presentation-only dashboard
   - 无法执行到结果的演示流程
3. 如果依赖上述内容，明确标记为 demo-driven drift 风险
4. 把方案改写成更小的真实闭环版本，优先保留：
   - 可执行操作
   - 明确输入输出
   - 用户可拿到真实结果
5. 如果必须保留壳层表达，限制为轻量入口或空状态，不要伪装成已经具备真实能力

## 自校验步骤

1. 这项变更是否直接加强了真实可用流程，而不是视觉上的“更丰满”
2. 是否移除了假数据驱动的核心价值叙述
3. 是否避免把展示内容包装成已落地能力
4. 最终建议是否落回更小、更真实的工具闭环

## 常见失败点

- 用 sample data 填充页面来证明价值
- 为了“像个平台”而扩出大量不可执行模块
- 把 graph showcase 或知识卡片重新推回主路径
- 空状态写成“功能已存在，只差接数据”的假完成感
