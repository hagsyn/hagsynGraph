# Workspace Shell Boundary SOP

## 适用场景

当任务涉及页面重构、工作区布局调整、导航改造、新模块入口、空状态设计、首页形态变化或壳层扩展时使用。

## 前置检查

1. 确认变更是否会影响工作台壳层，而不只是局部样式
2. 确认当前页面是否仍围绕本地单机工具工作流，而不是转向 landing page 或单纯展示页
3. 识别新增区域属于真实可用模块、未来壳层入口，还是装饰性占位

## 执行步骤

1. 先判断这次调整是在优化工作区承载，还是在把产品重写成宣传页/概念页
2. 检查以下边界是否被破坏：
   - 本地 workbench 定位
   - real tool first
   - 对未来模块的诚实表达
3. 对每个新增导航、面板或空状态，明确归类：
   - 已有真实能力
   - 合理保留的壳层入口
   - 不应出现的装饰性结构
4. 如果某部分只是未来方向，保留为轻量壳层，不要增加伪数据、伪指标或伪结果页
5. 输出建议时，强调哪些结构可以保留，哪些需要收缩或延后

## 自校验步骤

1. 页面是否仍然像工作台，而不是营销页或演示页
2. 壳层是否为真实后续工作留口，而不是制造完成假象
3. 新增结构是否服务真实任务路径，而不是单纯凑版面
4. 是否保住当前核心工具链路的可见性与优先级

## 常见失败点

- 把主界面改成 hero page 或宣发式首页
- 用大块概念卡片代替真实工具入口
- 空状态里放太多未经验证的未来模块内容
- 让当前真实工具被壳层结构挤到次要位置
